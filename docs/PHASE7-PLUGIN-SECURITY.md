# Phase 7: Plugin trust, integrity, and supply-chain security\n\nTermAgent 1.14 adds the security layer that sits between marketplace distribution and runtime component activation. The goal is to make changes in downloaded plugin content observable and to prevent path, identity, or content substitutions from silently inheriting trust.\n\n## Security state\n\nSecurity state is stored at:\n\n```text\n~/.termagent/plugins/security.json\n```\n\nThe parent directory is private (`0700`) and the file is private (`0600`). Writes use a temporary file followed by rename. The schema is versioned:\n\n```json\n{\n  "version": 1,\n  "blockedPlugins": ["plugin@marketplace"],\n  "blockedMarketplaces": ["marketplace"],\n  "revokedPlugins": {\n    "plugin@marketplace": {\n      "digest": "sha256:...",\n      "revision": "40-character-git-sha",\n      "reason": "security recall"\n    }\n  },\n  "revokedDigests": {\n    "sha256:...": "reason"\n  },\n  "revokedRevisions": {\n    "40-character-git-sha": "reason"\n  },\n  "trust": {\n    "plugin@marketplace": {\n      "source": "sha256-source-fingerprint",\n      "digest": "sha256:...",\n      "revision": "40-character-git-sha",\n      "approvedAt": "2026-09-27T00:00:00.000Z"\n    }\n  }\n}\n```\n\nMalformed policy JSON or schema data is an error. It is not converted into an empty policy. This keeps policy corruption fail-closed.\n\n## Trust lifecycle\n\nA plugin trust approval is bound to three inputs:\n\n```text\nsource fingerprint + exact content digest + exact Git revision\n```\n\nThe resulting trust state is one of:\n\n- `approved`: the stored tuple exactly matches the current plugin.\n- `unapproved`: no approval exists.\n- `invalidated`: an approval exists but at least one trust input changed.\n\nRemote marketplace installs require explicit confirmation unless an exact approval already exists. After a confirmed install, the exact tuple is persisted. A changed source, changed content, or changed revision requires confirmation again.\n\nEnablement also checks content integrity, policy revocation/blocklists, and persistent trust for object-based remote plugin sources.\n\n## Integrity verification\n\nPlugin content is hashed using a deterministic tree digest. Entries are sorted by path, directories and files are represented separately, file bytes are included, `.git` is ignored, and symbolic links are rejected. Installed state records the digest as `sha256:<64 hex characters>`.\n\nRemote Git plugin sources also record the materialized Git revision. When a source includes a recorded SHA, the checked-out revision must equal the requested SHA. The same revision is carried into the trust tuple.\n\nRemote marketplace manifests have their own manifest digest. `getMarketplace()` and marketplace reconciliation recompute the cached manifest digest and report a broken marketplace on mismatch instead of silently replacing the recorded digest.\n\n## Realpath containment\n\nLexical plugin component paths must already be relative `./...` paths with no `.` or `..` segments. Phase 7 adds the runtime layer: before reading an installed component, TermAgent resolves its realpath and verifies that it remains under the real plugin root. The check is applied to:\n\n- installed plugin roots;\n- recursive command and agent Markdown discovery;\n- manifest-declared command files;\n- MCP configuration files;\n- hook definition files.\n\nThis prevents a symlink from converting an apparently safe `./component` path into a read outside the plugin package. A plugin whose installed tree digest no longer matches the recorded digest is rejected before components activate.\n\n## Marketplace identity hardening\n\nReserved marketplace names are implemented from TermAgent the current design official-name policy. The TermAgent check is stricter than a simple substring match:\n\n```text\nhttps://github.com.attacker.com/anthropics/evil   -> reject\nhttps://evilgithub.com/anthropics/evil            -> reject\ngit@notgithub.com:anthropics/evil.git            -> reject\ngit@github.com:anthropics/real.git               -> allow\n```\n\nOnly exact `github.com` + first path/repository organization `anthropics` is accepted for reserved names. Direct `url` sources cannot claim a reserved official name.\n\n## Plugin blocklist and revocation\n\nThe local policy layer supports three useful forms:\n\n1. block a plugin or whole marketplace by name;\n2. revoke an exact content digest;\n3. revoke an exact Git revision or a plugin-specific digest/revision tuple.\n\nPolicy evaluation runs before install, before enablement, when computing installed plugin state, and before runtime component activation. A blocked/revoked plugin is returned as broken or rejected rather than activated.\n\n## Skill security scanner\n\nSkills are still prompt-only Markdown. the relevant TermAgent subsystem is implemented using TermAgent the current the skill registry validator concepts and scans every line, including fenced code. It normalizes text with NFKC while retaining the original line for hidden-Unicode detection.\n\nBlocked patterns include:\n\n- zero-width, BIDI, and Unicode tag characters;\n- hidden HTML comments;\n- fake `system`/`assistant`/`developer` markers and instruction-override phrases;\n- credential references paired with network URLs;\n- common exfiltration endpoints;\n- unsafe `curl`, `wget`, `fetch`, axios, requests, and PowerShell network fetch patterns;\n- base64/decode combined with `exec`/`eval`/shell execution;\n- absolute destructive `rm -rf`;\n- direct interpreter `-c` / `-e` execution snippets;\n- confirmation bypass and destructive `--yes` patterns.\n\nWarnings include raw IP URLs and mixed Latin/Cyrillic/Greek scripts as a confusable signal. A blocked skill is removed from discovery and cannot be loaded for the model. The live file is rescanned immediately before full-body invocation so a file changing after discovery cannot bypass the content policy.\n\n## Compatibility and boundaries\n\nThe Phase 7 layer does not import arbitrary downloaded JavaScript. Declarative plugin components continue to run through existing TermAgent command/agent/MCP/hook loaders and the existing permission gate. Legacy local `.js`/`.mjs` plugins remain a separate compatibility path.\n\nNo remote security-feed dependency is introduced in this phase. Local revocation/blocklist state is enough to create the enforcement chokepoints; a future registry can supply policy data without moving enforcement out of the local runtime.\n\n## Verification\n\nPhase 7 focused coverage contains 13 adversarial tests plus the existing Phase 5 and Phase 2 regression suites. The focused tests cover hostile manifest paths, URL impersonation, marketplace cache tampering, exact trust persistence and invalidation, installed digest tampering, source/installed-root symlink escapes, revocations and blocklists, hidden Unicode and prompt-role injection, exfiltration/execution patterns, warning-only confusables, and corrupted security policy.\n
