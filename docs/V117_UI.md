# TermAgent 1.1.7 UI hardening

## Scope

This release completes the high-priority Q1 terminal interaction fixes discovered on a small ARMv7 Termux display. It is intentionally implemented without a heavyweight terminal UI framework or other native UI dependencies.
TermAgent's current `PromptInput` keeps the logical input, cursor offset, history, suggestions, and modal UI state separate and uses focused selection components for interactive lists. TermAgent's current TUI documentation provides the user-facing reference for slash commands, `@` file references, scrolling, thinking visibility, command palettes, editor actions, and keyboard behavior.

## Implemented behavior

### Slash picker

Typing `/` opens suggestions immediately. The filtered collection is retained in full; only eight rows are rendered at once. Up/Down changes the global selection index and the rendered window follows it. A range label makes off-screen navigation visible. Filtering remains prefix-first with fuzzy subsequence fallback.

### Command palette

`Ctrl+P` invokes the same selection state without overwriting the draft. Text typed while the palette is open changes the palette query. Backspace edits the query. Up/Down changes selection. Enter returns the selected slash command to the normal command dispatcher.

### Active-turn mouse safety

While a model turn is running, SGR and legacy mouse button input is consumed as non-interrupting terminal interaction. Wheel events remain available for conversation scrolling. A standalone Escape is delayed briefly before being promoted to an interrupt so a split mouse sequence cannot accidentally abort the model.

### Activity states

The fixed activity row reports meaningful execution state instead of leaving the user staring at a static prompt. Current phases include thinking, reasoning, writing response, running tool, permission required, retrying, and compacting context.

### Explicit reasoning

The provider adapters forward only explicit reasoning/thinking fields exposed in provider responses. TermAgent renders that content separately from the assistant response and keeps the panel collapsed by default. `Ctrl+E` and `/thinking` toggle the display. Display state never enables hidden model reasoning.

### Permission UI

Interactive permission requests use a focused `SelectModel` with Allow once, Always allow, and Reject. The selection owns stdin while visible. Approval changes the associated tool from `awaiting approval` to `running`; denial fails closed.

## Verification

The compiled CLI was exercised in a real pseudo-terminal. Screens were reconstructed from the ANSI/VT stream at 80x24 and 60x20 and manually inspected. Covered states include slash picker, picker navigation beyond row 8, filtering, multiline cursor editing, model activity, reasoning expansion, permission approval, final response streaming, and conversation scrolling.

The automated suite contains 49 tests and runs with `npm test`.

## Escape-sequence hardening

Terminal Escape is ambiguous: a single byte can mean an interrupt, while the same prefix begins cursor, mouse, paste and other control sequences. The prompt editor now gives a lone ESC a 70ms grace window before handling it as the normal Escape action. Multi-byte sequences cancel that grace timer and are parsed normally. This prevents a split terminal event from poisoning the editor's input buffer after closing a palette or suggestion surface.

The final PTY verification explicitly exercises `Ctrl+P` -> filter -> `Esc` -> new text, followed by a running model turn and mouse input.
