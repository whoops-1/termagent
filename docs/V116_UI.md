# TermAgent 1.1.6 UI behavior

## Goal

The 1.1.6 interactive pass targets the interaction model of TermAgents without importing a heavyweight terminal UI framework or a native terminal renderer. The implementation is intentionally Node-standard-library + ANSI/VT so it remains viable on the ARMv7 Termux target.
- Prompt value and cursor offset are separate state, rather than deriving the cursor from terminal output.
- Suggestions are a bounded selectable collection with a focused index.
- The suggestion collection filters as the query changes and supports keyboard navigation.
- Permission approval is a focused selector that temporarily owns keyboard input rather than competing with the prompt editor.
- The footer reflects the currently focused interaction surface.

TermAgent's current `PromptInput` keeps `cursorOffset` explicitly and handles history only when the cursor is at the appropriate boundary. Its current code is substantially larger and framework-specific terminal UI-based, so TermAgent uses the behavioral/state patterns rather than importing that UI runtime.

## Command picker

Typing `/` opens the command picker immediately. It exposes at most eight entries. Typing additional characters filters the list using prefix matches first and subsequence matches second. Up/Down changes the focused item. Enter and Tab accept the focused command. Escape closes the picker.

The picker is rendered above the composer so the composer remains the stable editing surface. The same logical cursor remains active in the prompt buffer.

## Chat scrolling

Conversation content is a separate viewport from prompt editing. PageUp/PageDown and Ctrl+Up/Ctrl+Down adjust the conversation scroll offset. SGR mouse wheel events use the same offset. Ctrl+Home/Ctrl+End jump to the oldest/newest conversation content. Prompt history is not changed by these scroll actions.

The alternate screen remains active. This means Termux's terminal scrollback is not the chat viewport; the application owns chat scrolling just like a full-screen coding-agent UI.

## Permission surface

A pending permission request changes focus from the composer to a selector. The shell command is displayed with an `awaiting approval` tool state and the selector offers Allow once, Always allow, and Reject. Arrow keys, j/k, Enter/Space, numeric keys, y/a/n, Home/End, and Escape are handled by the selector. Prompt keystrokes are not processed while the permission request owns stdin.

## Provider retry behavior

An empty provider turn, meaning neither text nor a tool call was emitted, is now treated as a retryable failure. The status callback exposes the retry attempt. After the retry budget is exhausted, the error is surfaced instead of silently returning to an empty composer. This closes the failure mode observed when a first or second provider request produced no visible response.

## 1.1.7 Q1 hardening

The command suggestion collection is intentionally larger than its viewport. At most eight rows are painted, but Up/Down operates on the complete filtered collection and the painted window follows the focused item. This prevents the eighth visible row from becoming an artificial selection boundary.

During an active model turn, terminal mouse input is parsed separately from interrupt input. SGR and legacy mouse clicks are ignored, wheel events scroll the conversation, and only an actual Ctrl+C or standalone Escape interrupts the turn. This matters on Termux because touch input arrives as terminal control sequences rather than as a semantic click event.

Live activity is a first-class UI state. The renderer reports thinking, provider reasoning, response writing, tool execution, permission waiting, retrying, and compaction without duplicating the same state into multiple status rows. Explicit provider reasoning can be expanded with Ctrl+E while a turn is running and `/thinking` can toggle its visibility from the normal prompt.
